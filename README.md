# ebook-capture

화면의 지정 영역을 일정 간격으로 자동 캡처하고, 다음 페이지 버튼을 클릭해 나가다가
진행률 100%에서 멈춘 뒤, 모은 JPG를 무손실로 하나의 PDF에 묶습니다. macOS 전용입니다.

## 사전 준비

**시스템 설정 > 개인정보 보호 및 보안**에서 두 항목을 허용해야 합니다.

- **화면 기록** — 없으면 캡처가 검은 화면만 반환합니다
- **손쉬운 사용** — 없으면 자동 클릭과 ESC 중단이 동작하지 않습니다

권한은 python이 아니라 **이 프로그램을 실행하는 앱**(터미널 / VS Code)에 부여합니다.
허용 후 앱을 완전히 종료했다 다시 여세요.

```bash
brew install tesseract
```

**어디서든 쓰려면 (권장)** — 전역 명령으로 설치합니다.

```bash
uv build
uv tool install --force ./dist/ebook_capture-0.1.0-py3-none-any.whl
ebook-capture --help
```

설치 후에는 아무 폴더에서나 `ebook-capture` 로 실행하면 되고, 결과는
**실행한 폴더의 `result/`** 에 저장됩니다. `--out` 으로 바꿀 수 있습니다.

**개발용** — 저장소 안에서 작업할 때.

```bash
uv venv --python 3.12
uv pip install -e ".[dev]"
uv run python scripts/preflight.py   # 권한과 클릭 동작 확인
```

## 사용법

```bash
uv run ebook-capture
```

제목과 간격을 물어본 뒤, 순서대로 클릭해서 지정합니다.

1. 캡처 영역 좌상단 → 우하단
2. 다음 페이지 버튼
3. 진행률(%) 표시 영역 좌상단 → 우하단

미리보기 2장이 `result/<제목>/`에 저장됩니다. **확인 후 y를 눌러야 시작**합니다.
미리보기 이미지가 완전한 단색이면(예: 새까만 화면) 화면 기록 권한이 실제로는
아직 적용되지 않았을 수 있다는 경고가 함께 출력됩니다 — 다만 진짜 빈 화면일
수도 있으므로 강제 종료하지 않고 계속 진행 여부를 사용자가 판단하게 합니다.
5초 카운트다운 뒤 자동 캡처가 시작되며, **ESC는 이 5초 카운트다운이 도는 동안에도
포함해 언제든 즉시 중단**됩니다.

제목마다 `result/` 아래에 전용 폴더가 만들어지고, 모든 산출물이 그 안에 들어갑니다.

```
result/
  <제목>/
    <제목>_p001.jpg ... <제목>_pNNN.jpg
    <제목>.pdf
    <제목>.session.json
    _preview_capture.png
    _preview_progress.png
```

`--resume`은 제목만 줘도 되고 세션 파일 경로를 줘도 됩니다.

```bash
uv run ebook-capture --resume "<제목>"
uv run ebook-capture --resume result/<제목>/<제목>.session.json
```

폴더 구조가 생기기 전에 `result/` 바로 아래에 저장된 세션도 그대로 찾아서 재개합니다.
`--resume`은 저장된 영역·클릭 지점 설정을 그대로 재사용하는 것은 물론,
세션 파일이 있는 폴더의 마지막 페이지 번호 다음부터 이어서 캡처합니다(예: `p010`까지
있으면 `p011`부터). `--resume` 없이 같은 제목으로 다시 실행하면 기존
페이지를 덮어써 두 번의 캡처가 뒤섞이므로, 이 경우 경고를 띄우고 `d`를
입력해야만 기존 파일을 지우고 처음부터 시작합니다. 단, `d`를 입력해도
실제 삭제는 그 자리에서 바로 일어나지 않습니다 — 이어지는 미리보기
확인에서 `y`를 눌러 최종 확인을 마친 다음에야 기존 파일을 지웁니다.
미리보기에서 취소하면(`y`가 아닌 다른 키) `d`에 동의했더라도 기존
파일은 그대로 남습니다.

`--resume`으로 재개할 때 현재 디스플레이 배율이 1.00x가 아니면, 저장된
좌표가 세션을 저장할 당시의 화면 설정과 맞지 않을 수 있다는 경고가
출력됩니다(좌표 자체를 배율에 맞춰 자동 변환하지는 않습니다).

## 옵션

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--title` | 대화형 | PDF 제목 |
| `--interval` | 대화형 | 캡처 간격(초) |
| `--fullscreen` | 꺼짐 | 영역 지정 대신 디스플레이 전체 캡처 |
| `--dpi` | 300 | JPEG DPI 메타데이터 |
| `--quality` | 95 | JPEG 품질 |
| `--page-size` | 없음 | `a4` 지정 시 PDF 페이지 박스를 A4로 배치 |
| `--max-pages` | 2000 | 안전 상한 |
| `--resume` | — | 저장된 세션 JSON으로 재개하고, 기존 페이지 다음 번호부터 이어서 캡처 |

## 간격(`--interval`) 정하기

클릭 후 뷰어가 다음 페이지를 실제로 그리는 데 걸리는 시간은 뷰어와 페이지 내용마다 다르기
때문에, 모든 경우에 맞는 고정값은 없습니다. **2초부터 시작**해서 아래 스크립트로 검증하는
것을 권장합니다. 같은 이미지가 연속으로 저장되면 간격이 렌더링보다 짧다는 뜻입니다.

```bash
uv run python - <<'EOF'
from pathlib import Path
from PIL import Image, ImageChops, ImageStat
from ebook_capture.naming import sort_pages
pages = sort_pages(list(Path("result").glob("테스트_p*.jpg")))
for a, b in zip(pages, pages[1:]):
    with Image.open(a) as x, Image.open(b) as y:
        diff = ImageStat.Stat(ImageChops.difference(x.convert("L"), y.convert("L"))).mean[0]
        print(f"{a.name} -> {b.name}: 평균 차이 {diff:.2f}", "중복 의심!" if diff < 2 else "")
EOF
```

3~5쪽짜리 짧은 구간(`--max-pages 5`)으로 먼저 시도해 간격을 확정한 뒤 전체를 돌리세요.

## 화질에 대해

화면 캡처는 화면에 있는 픽셀 수만큼만 존재합니다. `--dpi 300`은 **픽셀을 늘리지 않고
DPI 메타데이터만 기록**하므로 화질 손실도 없고 파일이 커지지도 않습니다.

**실제 화질을 높이는 유일한 방법은 캡처 전에 뷰어 창을 최대한 크게 키우는 것입니다.**
4K 모니터에서 세로로 꽉 채우면 페이지 픽셀이 크게 늘어납니다. 실측으로도 확인된 사실입니다:
같은 뷰어를 작은 창으로 캡처했을 때는 페이지가 1105×1776px(PDF 94×150mm)였지만, 같은 4K
모니터에서 창을 최대한 키운 뒤 다시 재보니 3200×2050px(PDF 271×174mm)까지 늘었습니다 —
창을 키우는 것만으로 지면 픽셀이 약 3배가 된 것입니다.

`--dpi`와 `--page-size`는 PDF 페이지의 표기 크기만 바꿉니다. 셋 다 화질은 동일합니다.

## 진행률 영역을 잡는 법

진행률 영역은 빡빡하게 잡을 필요가 없습니다. `%` 기호가 앵커 역할을 해서 판독기가
숫자와 `%`를 함께 찾기 때문에, 영역을 넉넉하게 크게 잡아도 (제목 텍스트가 같은 줄에
붙어 있어도) 진행률만 정확히 읽습니다. 오히려 너무 좁게 잡아서 `%`가 잘리는 쪽이
더 위험합니다.

## 종료 조건

1. 진행률 OCR이 100% 이상을 읽음
2. 화면이 3회 연속 동일 (OCR 실패 대비 폴백 — 뷰어가 진행률을 100%까지 올리지 않고
   99%에 머무르거나 마지막 페이지에서 갱신을 멈추는 경우에도 이 폴백이 캡처를 정상적으로
   끝냅니다)
3. `--max-pages` 도달
4. ESC

## 알려진 제약: 여러 프로세스 동시 실행 금지

ESC 감지는 pynput 전역 키보드 리스너로 구현되어 있습니다. 같은 프로세스 안에서 이
리스너를 여러 번 생성하면 macOS에서 `pynput/_util/darwin.py`의 `keycode_context` 내부에서
SIGABRT로 강제 종료됩니다. 정상적인 1회 실행(`ebook-capture` 한 번 구동)에서는 리스너가
1개만 만들어지므로 안전합니다. 하지만 **테스트 스위트를 여러 프로세스로 동시에 돌리면
크래시할 수 있습니다** (측정: 순차 16회 실행 시 크래시 0회, 동시 9회 실행 시 크래시 1회).
`uv run pytest`는 항상 한 번에 하나씩만 실행하세요.

uv run pytest              # 자동 테스트
uv run pytest -m manual    # 실제 화면을 클릭하는 수동 테스트
